# Use the LLM for preference interpretation and hall choice

The recommendation pipeline already asked Workers AI to pick five dishes, but the candidate set, the scores, the weights, and even the dining hall came from deterministic code. This change moves the LLM one step earlier: it converts the free-text food preferences (English or Chinese) into English search terms, and it chooses the dining hall from a hall-level summary. Hard dietary filters, eligibility, and weights still never leave the Worker.

Interpretation is a separate Workers AI call with a JSON schema and a small sanitizer: lowercase words, at most 24 characters, deduplicated, capped at eight keywords, six wants, six avoids, and four flavors. The result is cached in D1 per account and keyed by the likes text plus the model name, so repeated requests skip the call. A fallback is never cached, so an AI outage is retried on the next request. Interpreted terms extend the literal keyword list instead of replacing it, and avoided ingredients only scale the food score by 0.25; nothing the model returns can filter a dish out or relax a dietary label.

The ranking prompt now also receives the hall summary (matching candidate count, top and average score, the saved location rank) and an "interpreted preferences" line. The model's `best_location` is validated: an accepted hall must contain a pick, so a hall without one is filled with its highest-scoring candidate before the shortlist is topped up; a full shortlist that ignores its own hall falls back to the first pick's location. The response exposes `preference_interpretation` and `best_location_source`, and the results panel shows the interpreted terms.

Failure handling stays total: no AI binding, a timeout, invalid JSON, an empty interpretation, or a missing cache table all degrade to the existing keyword matching and rule-based reasons. The pipeline starts the interpretation at the same time as the menu requests, caps it at six seconds, and the frontend request timeout was raised to 60 seconds for the two-call cold path.

Migration `0007_preference_interpretations.sql` adds the cache table. Worker tests cover sanitization, the prompt delimiting, cache hits and failures, non-English likes activating food scoring, avoided-term demotion, hall acceptance, hall filling, weighted hall fallback, and repeated requests sharing one interpretation call. Deferred: letting the model build the shortlist itself, feeding ingredient details into the prompt, conversational refinement, and an acceptance-rate dashboard.
